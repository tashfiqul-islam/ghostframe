## E. Components

Each component lists: purpose, anatomy (an 80-column mock for the left half, a 72-column mock for the pane, unless stated), states, streaming or update behaviour, narrow behaviour, and the render site. Each heading says what happened to the component since v6: **kept** (the v6 rules hold as written; they are restated so this document stands alone), **changed**, or **new**. "Site" names follow the plugin API; **probe n** points at section I.

Where something lives, decided case by case:

| Thing | Docked | Fallback | Why |
|---|---|---|---|
| Your prompt, steer, queued message | left | left | they are the conversation |
| Claude's answer, an interim report | left | left | they are the conversation |
| A sentence Claude says while working | pane `[ NOW ]`, then the full view | live now-row, then ctrl+o | it describes the work, it is not addressed to you |
| A passing step | pane | counted in the capsule | the expected case |
| A failed or blocked step that is later fixed | pane (`✕`, then `✓`); the receipt says `1 failure → fixed` | `✕` row at once; the capsule says `→ fixed` | it did not change the answer; without a pane the row is the only live signal |
| A failure or block that is never fixed | pane, and a `still failing` row above the receipt | the `✕` row it already drew | it changed the answer (principle 12) |
| Permission prompt | the engine's dialog at the prompt; pane `[ NOW ]` shows the step that asked | dialog and a live `! needs you` row | you must act |
| Your permission decision | left for `denied` and `always allow`; pane only for `allowed once` | the same | a denial changes the answer, a standing rule changes the future, a single allow changes nothing |
| Question card and its answer | card at the prompt, answer row left | the same | you must act; your answer is your words |
| Plan and your verdict | left | left | a plan is a document you approve |
| Commit | pane (`±`), and the answer usually names it | counted in the capsule | local and reversible |
| Push, pull request, merge, release, deploy | left, at once, and the pane step (`↗`) | left, at once | it left the machine; you will scroll back for the link |
| Agents | pane roster | live roster, then the capsule | work |
| To-do list | pane | one live row; `/todo` prints it | work |
| Files changed | pane; count in the receipt | count in the receipt; `/files` prints the table | work |
| Sources that the answer cites | left, in the answer's `[ SOURCES ]` frame, and marked in the pane | left | answer content |
| Pages read but not cited | pane only | ctrl+o | work |
| API errors, limits, context warnings | left | left | you must act or wait |
| Notices (MCP, updates, memory saves, compaction, resume) | left | left | they are about the session, not a turn |
| Thinking | pane | live now-row | time, not content |

### E.1 Turn boundary · changed

**Purpose.** Make a turn one unit: a solid labelled rule opens it, a solid receipt closes it. Solid rules appear nowhere else.

<<e-turn>>

- **Anatomy.** Opening rule: `─` at column 0, `[ TURN n ]` from column 2, rule fill, wall clock (24h) ending on the time edge. Closing rule (the receipt, E.32): `─`, the state word and `· turn n` from column 2, rule fill, then counts and the total duration ending on the time edge.
- **What changed.** The receipt repeats the turn number, because the number is now an address: `/steps 7` pins that turn in the pane, and on a long answer the opening rule is far above the receipt.
- **States of the label.** `[ TURN 14 ]`; `[ TURN 15 · RESUMED ]`; `[ TURN 31 · AFTER COMPACT ]`; `[ TURN 13 · AFTER REWIND ]`. When the calendar day differs from the previous turn's, the clock becomes `Thu 19 Nov · 09:02`.
- **Streaming.** The opening rule draws once, with the prompt. The receipt draws once, at turn end. If a turn has no receipt (probe 3), the next turn rule closes it.
- **Narrow.** Below 72 columns the receipt drops fields from the left of its meta (E.32). Duration and state word are never dropped.
- **Site.** Opening rule: `UserMessage` where `origin.kind` is `composer`, as the first row of its tree. Receipt: `TurnDuration`.

### E.2 User prompt · kept

**Purpose.** Your words are the landmark you scroll for. They get the only accent glyph and the only full-width background on the left.

<<e-prompt>>

- **Anatomy.** `▍` (accent) in column 0 on every row of the prompt, text from column 2 in text-bright, `surface` background from column 0 to F−1. The background stops at F: it never runs under the divider.
- **States.** *Short*: one row. *Multi-line*: one bar per row, wrapped at the block measure, never truncated up to 6 rows. *Long paste*: the first 3 rows, then one muted row `… n more lines · pasted · ctrl+o`; the cut is decided at first draw. *@file mention* and *attachment*: a chip with no padding cells; an image is `[ image n ]`. *Steer* and *queued*: E.20.
- **Narrow.** Wraps at F. A path chip that does not fit moves whole to the next row; a chip longer than the row is cut in the middle (`hooks/…/register.tsx`).
- **Site.** `UserMessage`. Its `isExpanded` prop is true in the ctrl+o view **(types)**, where the full paste is drawn.

### E.3 The capsule · new (replaces the rail)

**Purpose.** Fallback mode's whole account of a stretch of work, in one row. It is what the pane's `[ STEPS ]` section becomes when there is no pane.

<<e-capsule>>

<<e-capsule-60>>

- **Anatomy.** `│` (rule-strong) in column 0. Then, in muted: `worked`, the step count, up to three kinds by count (`6 shell · 5 read · 2 test`) and `+n` for the rest, and the exception story. The turn clock at which the stretch ended is on the time edge, dim.
- **The exception story** is the last field and the only coloured one: `1 failure → fixed` (muted: it ended well), `1 failure` (err), `1 blocked` (warn), `7 agents · 6 done · 1 failed`. Zero exceptions: the field is absent.
- **When a capsule is drawn.** It closes a stretch of work, and it is always drawn by something that is being drawn anyway, so nothing is edited afterwards:
  1. when a block of Claude's text that stays in the transcript starts (the answer, or an interim report): the capsule is the first row of that block's tree, and at that moment every step before it has finished;
  2. when 5 minutes have passed with no new transcript row and a step ends: that step's own site draws a capsule for the stretch so far, so a long silent turn leaves a trail (scenario F.5 has nine of them in 51 minutes);
  3. when a turn ends without any text: the receipt's site draws it above the receipt.
- **What it never does.** It is never updated. A stretch that is still running is in the live area (E.33), not in a capsule.
- **Zero steps:** no capsule. **Thinking only:** `│ thought` and the time, when thinking took more than 10 seconds.
- **Narrow.** Kinds give way first, from the right, folding into `+n`: three kinds from 72 columns, two below, then one, then none. Below 60 columns the clock is dropped too (the receipt keeps the total). The step count and the exception story are never cut (the last two rows of the second mock are 50 columns wide).
- **Not drawn when docked.** The pane has the steps and the receipt has the counts (principle 10).
- **Site.** `AssistantMessage` (case 1), `ToolUse` (case 2), `TurnDuration` (case 3). Case 1 depends on the same fact as v6's fold: knowing that a text block will stay (probe 1).

### E.4 The unfolded view (ctrl+o) · changed

**Purpose.** The complete record as plain text: every sentence, every step under the sentence that announced it, every turn, in order.

<<e-unfold>>

- **How ctrl+o works in Cockpit.** It is still the engine's switch. In that view the engine raises one `ToolUse` row per call and folds nothing **(types)**, and the plugin draws each row as below instead of passing it to the engine's grey slab. The pane stays where it is and keeps showing one turn; ctrl+o shows all of them inline. The two differ by job: the pane is live and you glance at it; the unfolded view is still, and you read, search and copy it.
- **Anatomy.** A sentence Claude said while working is a `│` row in muted with the turn clock; it wraps instead of being cut. Step rows continue the bar and are inset to column 4: kind word (muted, 8 cells), subject (text), result word right-aligned at column F−10, the step's *own* duration on the time edge (the only place it is shown; everywhere else the clock is the turn's).
- **Result words.** A result is a noun phrase taken from the tool's output, never `ok`: line counts for `read`, `+n −n` for `edit`, the exit summary for `shell`, `n pass` or `n of m fail` for `test`, the HTTP status for `fetch`, `n matches` for `search`. Colour only when it is not the expected result.
- **Diffs and output** appear here in full, in frames (E.8), directly under the step that produced them (scenario F.8).
- **Same rows as the pane's full view** (E.44). `/steps 7 all` prints exactly these rows for one turn into the transcript, as a command's output.
- **Narrow.** Result word drops below 72 columns; duration below 60.
- **Site.** `ToolUse` with `isExpanded` true **(types)**; `AssistantMessage` for the sentences.

### E.5 Exception and event rows · changed

**Purpose.** The few results that belong in the conversation: something left the machine, you decided something, you must act, or something failed and stayed failed.

<<e-exc>>

Docked (above). In fallback every failure and block draws at once, because there is no pane to show it:

<<e-exc-fall>>

- **Anatomy.** Glyph (coloured) in column 0; an optional bold state word followed by ` · `; the kind word and subject in text; the turn clock on the time edge. Up to 3 detail rows may follow at column 4 in muted: the decisive lines of the error, chosen at draw time.
- **Which results get a row, and when.**

| Row | Docked | Fallback |
|---|---|---|
| `↗` push, pull request (with its URL on a detail row), merge, release, deploy | at once | at once |
| `▍ denied`, `▍ always allow` | at once | at once |
| `!` limit, context, final API error | at once | at once |
| `✕ failed` | not drawn; the pane has it | at once |
| `⊘ blocked` | not drawn; the pane has it | at once |
| `✕ still failing`, `⊘ still blocked` | at turn end, above the receipt, for each failure or block that nothing later fixed | not needed: the row above already exists |
| `✓` a passing check | never; the receipt says `→ fixed` | never; the capsule says `→ fixed` |
| `±` commit | never; it is a pane mark and usually a sentence of the answer | never |

- **Why `still failing` is honest.** At the moment a test fails nobody knows whether it will be fixed. Docked, the pane shows it that second. The transcript waits until the turn ends, and then states only what stayed true. A row drawn at turn end carries the clock of the failure, not of the turn end, so it still reads as a timeline.
- **"Fixed" means:** a later step of the same kind and subject (the same command, the same file) succeeded in this turn. Anything else is still open.
- **No row is ever amended.** Recovery is a count in the receipt or capsule, never a word written back onto a row.
- **Narrow.** Subject is cut with `…` before the clock; the state word and glyph are never cut.
- **Site.** `ToolUse` for rows drawn at once; `TurnDuration` for the rows above the receipt (probe 3: whether its tree may be several rows).

### E.6 Thinking · changed

**Purpose.** Thinking is time, not content. It is shown as time, in the pane.

<<e-think>>

- **Running.** `[ NOW ]` keeps the last sentence Claude said and shows `thinking` with its own elapsed time on the second row. The left now-row says `working` as always.
- **After.** One `∴ thought` row in `[ STEPS ]` with the turn clock, only when the thinking took more than 10 seconds. Shorter thinking leaves nothing.
- **Unfolded and full view.** `∴ thought` plus the summary text in muted italic (E.4).
- **Fallback.** No row. The live now-row says `thinking`, and a capsule that covers only thinking says `│ thought`.
- **Site.** `Spinner` (`mode` is `thinking` **(types)**) feeds the pane's state; expanded: probe 6.

### E.7 The answer · kept

**Purpose.** The thing you asked for. Blank spine, text weight, full structure. In Cockpit it is nearly the only thing on the left.

<<e-answer>>

- **Lead sentence.** The first sentence of the last prose block of a turn is text-bright; it should be the verdict. The plugin does not write it, it only lights it.
- **Verdict.** The state word of the receipt directly under the answer. Lead above, verdict below, body between.
- **Headings.** Level 1: bold text-bright with a hairline row under it and 2 blank rows above. Level 2: bold text-bright. Level 3: bold text. Level 4 and deeper: bold muted. No `#` marks are drawn.
- **Lists.** `-` at the content column, text 2 cells in; nesting is +2 per level, to 4 levels, then flattened. Numbers are right-aligned to the widest number known at first draw. Task lists draw `[ ]` and `[x]` as typed.
- **Quotes.** `▏` at column 2 in muted, body at column 4 in muted.
- **Inline code.** Text-bright on `chip`, with no padding cells, so the grid is not shifted and copy is exact. With `NO_COLOR` the backticks are drawn instead.
- **Interim report.** A block of Claude's text that is followed by more work stays in the transcript when it is structured (it has a table, a code fence, a list or a heading) or longer than 3 wrapped rows. It draws like an answer without the bright lead. Short plain narration does not stay: it goes to `[ NOW ]` (E.38).
- **Streaming.** Rows append at the bottom. A word that would overflow moves to a new row before it is drawn, so no row reflows. Every prose block starts bright; if a tool call follows and the block is narration, the block leaves the transcript in one frame (the fold, probe 1) and its sentence appears in the pane.
- **Narrow.** Prose wraps at F. Nesting insets shrink to +1 per level below 60 columns.
- **Site.** `AssistantMessage`.

### E.8 Code blocks · kept

**Purpose.** Code that can be read and copied exactly.

<<e-code>>

- **Anatomy.** A frame: `┄ [ language ] ┄┄┄ meta`, code rows on `surface` from column 2, a closing `┄` rule. Columns 0 and 1 of code rows are blank and on the base background. No line numbers, no side borders.
- **Syntax colour.** Almost none: code is text, comments are muted. In a diff, added rows are ok-green with `+` in column 2, removed rows are err-pink with `-`, context rows have a space. The sign is part of the row, so a copied diff is a valid patch body.
- **States.** *Short*: identical, never inlined. *Long*: every row is drawn; an answer is never cut. From 80 rows up, the closing rule repeats the label. *Several languages*: one frame each, 1 blank row between.
- **Long lines.** A row longer than the measure continues on the next row with `↩` in column 0.
- **Streaming.** The label rule draws when the fence opens; the file name and line count go on the closing rule when streamed. Rows append.
- **Copy.** Selecting rows yields the code with a uniform 2-space indent. `/copy code n` puts fence *n* of the last answer on the clipboard without the indent (E.24).
- **Site.** `AssistantMessage`.

### E.9 Links, footnotes and Sources · changed

**Purpose.** Links without OSC 8: readable in the sentence, complete and selectable at the end. The answer's sources and the pane's sources are one numbered list seen from two sides.

<<e-sources>>

- **In prose.** A Markdown link draws its text followed by a superscript mark in link-blue. A bare URL in prose is drawn as `host/…/last-segment` plus a mark. Marks are numbered in order of first appearance, which is stable while streaming.
- **The frame, on the left.** One entry per mark, and only for marks: mark, host (web-teal), page title; then the full URL on its own row, underlined, link-blue, from column 4. A URL row is never cut: Windows Terminal makes a plain URL clickable only when it is unbroken. A URL longer than the row wraps at the last `/`, `?` or `&` that fits, with `↩` in the spine.
- **What changed.** v6 listed pages that were read but not cited in this frame. They now live only in the pane (E.43). The frame is answer content: it holds exactly what the answer stands on, it is selectable, and it survives without a pane. The pane's `[ SOURCES ]` is the reading log: every page fetched, with its HTTP status, as it happens.
- **The relationship.** While the turn runs, the pane lists each page with `·`. When the answer cites a page, the same row gains the answer's mark. So `¹` in a sentence, `¹` in the frame and `¹` in the pane are the same page, and a `·` row in the pane is a page Claude read and did not use.
- **States.** *Footnotes only* (links, no web work): the frame is labelled `[ LINKS ]` and the pane has no `[ SOURCES ]` section.
- **Streaming.** Marks appear with their sentence. The frame draws once, when the block settles.
- **Narrow.** Host and title share a row until 60 columns; below that the title moves to its own row.
- **Site.** `AssistantMessage` (the final block of the turn); the pane rows come from `tool.call` on the web tools.

### E.10 Figures · kept

**Purpose.** Framed ASCII figures (mdxcn fences) arrive with their own frame. Cockpit does not add a second one and never reflows them.

<<e-figure>>

- **Detection.** A fenced block with no language (or `text`) whose first row matches `+-… [ TITLE ] …-+`.
- **Paint.** Frame characters dim, title muted, body text. Inside a figure the figure's own glyphs keep the figure's meaning; table D governs Cockpit's rows, not quoted art.
- **Background.** None: a figure is not code. **Caption.** A muted row under it when the next paragraph starts with `Figure`.
- **Streaming.** Buffered like a table: a figure draws only when its closing row has arrived.
- **Narrow.** A figure wider than the measure is not wrapped or scaled. It is cut at the frame edge, with one muted row under it: `figure is 64 cells wide · window shows 57`. Docked at 110 columns the transcript is only 67 wide, so this case is more common than it was; the row also says `/cockpit off widens the transcript`.
- **Site.** `AssistantMessage`.

### E.11 Tables · kept

**Purpose.** Data on the grid: no vertical lines, one rule, alignment by type.

<<e-table>>

- **Anatomy.** Header row in muted; a rule-strong `─` rule across the block measure; body rows in text; every second body row on `zebra`. Columns are separated by at least 3 blank cells. No outer frame, no column lines.
- **Column widths** are computed once, from the whole table, before it draws. Each column gets its longest cell up to a cap of 40; remaining width goes to the widest text column; a column that still does not fit wraps its cells to at most 3 rows and then cuts with `…`.
- **Shapes.**

| Shape | Rule |
|---|---|
| plain | as above; text left-aligned |
| numeric | numbers right-aligned on the decimal point; unit in the header; negative uses `−` (U+2212); a total row is preceded by a hairline rule and is bold |
| comparison | first column is the row label in muted; cells are `yes` / `no` / a value, never ticks alone |
| status | status is a word, coloured by meaning: `pass` ok, `fail` err bold, `skip` muted, `flaky` warn |
| key and value | 2 columns, no header and no rule; keys muted, values text |
| before → after | "before" cells muted, "after" cells text; a `→` column between exactly 2 value columns |
| wide | pivots: each row becomes a key and value record under a dotted rule `┄ [ 3 of 12 ] ┄` |
| long (over 40 rows) | every row is drawn; the header and rule repeat every 40 rows |
| empty | header, rule, then one muted row: `no rows` |

- **Streaming.** A table is buffered. One muted row stands in for it at the bottom of the block: `table · 4 rows so far`. When the first non-table line arrives, the placeholder is replaced by the finished table (scenario F.30).
- **Narrow.** The same algorithm with a smaller measure: caps drop to 24, then cells wrap, then the table pivots.
- **Site.** `AssistantMessage`.

### E.12 Tool kinds · changed

One vocabulary for every tool, used in four places: `[ NOW ]`, a `[ STEPS ]` row, an unfolded step row, and (for exceptions and events) a transcript row.

| Kind | Tools | Subject | Result | Mark it can earn in the pane | Transcript row |
|---|---|---|---|---|---|
| `read` | Read, image and PDF reads | path, `:lines` if ranged | `884 lines` | `✕` not found | only if never fixed |
| `edit` | Edit, MultiEdit | path | `+3 −1` | `✕` no match, `⊘` blocked | only if never fixed |
| `write` | Write | path | `+156` | `⊘` blocked | `●` when the path is a memory file (E.26) |
| `search` | Grep, Glob, LSP | pattern, then `in path` | `41 matches` | none: 0 matches is a result | none |
| `shell` | Bash, PowerShell | the command | exit summary: `clean`, `exit 1`, last line of stdout | `✕` non-zero exit, `±` commit, `↗` push, PR, merge | `↗` at once |
| `test` | a shell call whose command is a test runner | the command | `191 pass`, `2 of 14 fail` | `✕` failures, `✓` recovery or final check | only if never fixed |
| `web` | WebSearch | the query in quotes | `8 results` | `✕` | none |
| `fetch` | WebFetch | host and path | `200 · 41 kB` | `✕` 4xx, 5xx, timeout | none; the page is in `[ SOURCES ]` |

| `ask` | AskUserQuestion | the question's header | your answer | `!` waiting, `▍` answered | the answer row (E.16) |

| `todo` | TodoWrite | `n items` | `3 of 7` | none | none |

<<e-kinds>>

- **Screenshots and images** are never drawn. The row names the file.
- **Site.** `tool.call` feeds the pane's state; `ToolUse` and `ToolGroup` draw nothing in the folded transcript (probe 2) and step rows in the unfolded one.

### E.13 Subagents · changed

**Purpose.** Agents are parallel work that you do not want to read. Docked, they live in the pane's roster (E.40) from launch to the end of the turn and leave no transcript row unless one fails for good. This section is the fallback.

<<e-agents-fall>>

- **Fallback roster** (live area, frame `[ AGENTS ]`): one row per agent, as in v6: `◇` and name in agent-lavender (22 cells, cut with `…`), the kind word and subject of its current step, its step count, its elapsed time. A nested agent is inset 2 cells; only 2 levels are shown. All 7 rows are shown when the band has room (it is capped at half the terminal's rows **(types)**); otherwise the oldest finished agents collapse into one row.
- **Launch and finish rows are gone.** v6 drew one row for the launch and one per finished agent. In fallback the capsule now carries them: `│ worked · 7 agents · 214 steps · 6 done · 1 failed`. A failed agent still gets its `✕` row at once.
- **Background agents** keep their roster after the turn ends (`[ AGENTS · BACKGROUND ]`), and the receipt says `waiting · n agents`.
- **Messages from agents** (`›`) and the engine's own "agent finished" rows are engine rows: probe 5 decides whether the plugin may draw them as nothing when docked. If not, they stay; they start with `◇` or `›` in column 0, on the grid.
- **Narrow.** Roster drops the subject, then the step count. Below 60 columns it is one row: `◇ 5 running · 2 done`.
- **Site.** `AbovePrompt` (roster); `ToolUse` for `Agent`; `UserMessage` for notifications (probe 5).

### E.14 To-do list · changed

**Purpose.** The plan of record is live. Docked it is the pane's `[ TODO ]` section (E.41) and the transcript shows nothing. This section is the fallback.

<<e-todo-fall>>

- **Fallback, live.** One row in the band: `▸`, the item in progress, `n of m`.
- **Fallback, on request.** `/todo` prints the list as a `[ TODO ]` frame, with the marks of that moment. v6 drew that frame automatically at the first write; in Cockpit nothing is written into the conversation that you did not ask for.
- **At turn end**, in both modes, the receipt carries `7 of 7 to-dos`, or `5 of 7 to-dos` in warn if the turn ended early.
- **Site.** `AbovePrompt`; `CommandOutput`; `Pane`.

### E.15 Permission prompts · changed

**Purpose.** The one moment the interface must stop you. The dialog is the engine's and no render site draws it; Cockpit owns everything around it.

<<e-perm>>

- **Waiting, docked.** The engine's dialog takes the place of the prompt box. The pane's `[ NOW ]` section turns to `! needs you · permission` with the step that asked on its second row, and that step's row in `[ STEPS ]` carries `!` and `needs you` (scenario F.36). The status line's mode cell says `needs you`. The left now-row disappears: nothing is running. The terminal bell rings once. There is no separate live row: the dialog itself is the call to action, and it is right there.
- **Waiting, fallback.** As v6: a live row `! needs you · permission · <kind> <subject>` above the dialog, because without a pane nothing else names the step (scenario F.9).
- **The dialog** (top of the mock) is the target look if a site ever reaches it: a `[ PERMISSION ]` frame labelled with the kind, the exact subject in text-bright, one line of consequence, numbered options with `▸` and a chip on the selected one. Today it is engine-drawn and takes the theme's colours only (probe 8).
- **Kinds and their subject line.** `shell`: the command. `edit` / `write`: the path and a diff frame cut to 12 rows. `fetch`: the host. `mcp`: `server · tool` and the arguments. `read` outside the project: the absolute path. Destructive commands add the consequence line in warn.
- **Outcomes.**

| Outcome | Transcript | Pane step |
|---|---|---|
| allow once | nothing | result `allowed once`, no mark |
| always allow | `▍ always allow · Bash(bun test:*) · this repo` | result `always allow`, mark `▍` |
| deny | `▍ denied · shell rm -rf dist` and your reason in quotes | result `denied`, mark `▍` |
| skipped by the auto-mode classifier | only if never resolved: `⊘ still blocked · … · auto-mode classifier` | result `classifier`, mark `⊘` |
| blocked by policy or hook | only if never resolved | result names who, mark `⊘` |

- **Site.** Outcome rows: `ToolUse` (`isErrored` is true for "a refusal at the dialog" **(types)**). The pane knows a dialog is up from `isPromptCovered` on its own props **(types)**.

### E.16 Ask-user question cards · changed

**Purpose.** Claude asks, you choose. The card is the engine's dialog wrapped in a frame; the answer becomes one of your rows.

<<e-ask>>

- **Card.** Frame label `[ QUESTION ]`, meta `n of m · single choice` or `choose any`. The question in text-bright; options numbered; `▸` and a chip on the current option; multi-select uses `[ ]` / `[x]`. The engine's dialog node is kept whole inside the frame: a tree for this site "holds the engine's node once" and at most 12 rows on the terminal **(types)**.
- **While it waits.** The pane's `[ NOW ]` says `! needs you · question · 1 of 1` with the question's header; the step row is an `ask` step with `!` (scenario F.12).
- **Answered.** One `▍` row on the left: the question's header in muted, `→`, your answer in text. In the pane the `ask` step's mark becomes `▍` and its result is your answer. The two say the same thing in two places on purpose: the left is the record, the pane row is the step's result like any other.
- **Skipped or dismissed.** `▍ no answer · How should it land?`
- **Site.** `AskUserQuestion` (the card); `ToolUse` for the tool (the answered row).

### E.17 Plan mode · kept on the left, new on the right

**Purpose.** A plan is a document you approve. It gets the largest frame on the left and a one-row verdict from you.

<<e-plan>>

- **Proposed.** `[ PLAN ]` frame; meta counts steps and files when the plan states them. The body is ordinary answer Markdown.

### E.37 The pane: sections, order and fitting · new

**Purpose.** Decide what is shown when everything does not fit, without anything jumping.

**Sections, in fixed order:** `[ NOW ]` (or `[ LAST ]` when idle), `[ STEPS ]`, `[ AGENTS ]`, `[ TODO ]`, `[ FILES ]`, `[ SOURCES ]`. A section with nothing in it is absent. The order is also the priority: if the engine ever clips the pane, it clips from the bottom.

The order is by how fast a thing changes and how soon you need it. `[ NOW ]` changes every second. Steps change every few seconds. Agents and to-dos change by the minute. Files and sources are reference. Nothing with a clock sits below something without one.

**Every section's label rule carries its own summary** (`5 running · 2 done`, `4 of 7`, `11 changed · +418 −388`, `8 read · 5 cited`). So a section can lose all its rows and still say the one thing that matters. That is the collapse step, and it costs nothing.

**The fitted layout.** The pane has `bodyRows` rows **(types)**. Cockpit draws a tree of exactly that height, so the engine never has to scroll it and `[ NOW ]` is always on screen:

1. The head (`[ NOW ]` or `[ LAST ]`) takes 3 rows. It is never dropped.
2. The lower sections are measured first, each up to its cap: `[ AGENTS ]` 7 rows (then `… n more`); `[ TODO ]` 3 rows around the current item (5 in a pane of 40 rows or more); `[ FILES ]` 4 rows, the last being `… n more files` (6 in a tall pane); `[ SOURCES ]` 3 rows (4 in a tall pane).
3. `[ STEPS ]` takes every row that is left, as a window on the step list (E.39). It is the only elastic section.
4. If `[ STEPS ]` would get fewer than 6 rows (3 in a pane under 24 rows), the lower sections give way in this order until it does: the blank rows between sections; `[ SOURCES ]` to its label; `[ FILES ]` to its label; `[ TODO ]` to its current item; `[ AGENTS ]` to running agents only; `[ AGENTS ]` to its label; `[ TODO ]` to its label; then the labels themselves, in the same order.

The ladder, on the model of E.36, at 56 columns and 22, 16, 11 and 7 body rows:

<<e-ladder-22>>

<<e-ladder-16>>

<<e-ladder-11>>

<<e-ladder-7>>

- **Sections do not move during a turn.** The layout is computed when the turn starts and again only when a lower section must grow (the first agent launches, the first file changes). When that happens `[ STEPS ]` gives up rows from its top, where the oldest steps fold into the `… n earlier` row, so the newest steps stay where they were, and everything below the new section's label shifts once. A lower section never shrinks before the turn ends.
- **Does CONTEXT / LIMITS earn a place?** No. The status line has all three meters at every width, the left has the `! needs you` row when one of them needs you, and a third copy would break principle 10. The one useful number the status line lacks, session cost, is one `/cost` away and would make the instrument look like a bill.
- **Height changes.** A change of height alone does not make the engine ask the pane to draw again **(types)**. If the window gets shorter while idle, the engine shows the top of the old tree and the bottom is clipped, which loses the least important section first. The next event (a step, a tick, a key) fits the tree again. Probe 27 measures how long that takes in practice.
- **Site.** `Pane`; `scroll.bodyRows` **(types)**.

### E.38 `[ NOW ]` and `[ LAST ]` · new

**Purpose.** The head of the pane. One glance answers "what is it doing?" while a turn runs, and "how did that end, and what is waiting?" when it does not.

<<e-now>>

- **Label rule.** `[ NOW ]`, and on the right the turn and the number of the step in progress.
- **Row 1, the sentence.** `▸` and the last thing Claude said about the work, in text, cut with `…`. This is where narration lives now: v6's rail sentences. It changes when Claude says something new, which is every few steps, so the eye has something slower than the step row to rest on. Before Claude has said anything it is the fixed phrase for the moment (`Waiting for the first token.`).
- **Row 2, the step.** Kind word (muted, 8 cells), subject (text-bright), the step's own elapsed time on the time edge. Several tools at once: the one that started first, plus `+2`.
- **Not here:** the turn's elapsed time (it is on the left now-row) and a spinner (the one on the left is the only animated cell on screen).
- **Needs you.** The label and row 1 turn to warn: `! needs you · permission` (or `· question · 1 of 2`, `· plan`). Row 2 is the step that asked, and its clock, now in warn, counts how long it has waited. Nothing else in the pane changes colour.

When no turn is running the head is `[ LAST ]`:

<<e-last>>

- **Label rule.** `[ LAST ]`, the turn and the wall clock at which it ended.
- **Row 1.** The state word (same word and colour as the receipt), the story in a few words (`1 failure → fixed · ± 7be09d2`), the turn's duration on the time edge.
- **Row 2, only when something is waiting**, in muted: an unresolved failure and what to do about it; background agents still running; the plan's next move. A turn that ended clean has no row 2.
- **What the idle pane shows below it.** The last turn, frozen exactly as it was when it ended: `[ STEPS ]` with its marks, `[ AGENTS ]` with their outcomes, `[ TODO ]` if any item is open or the list finished this turn, `[ FILES ]`, `[ SOURCES ]`. Nothing rearranges at turn end; only the head changes. It is not a session summary: the session's totals are one `/cost` away, and a summary would replace the one thing you look at the pane for after a long turn, which is what just happened.
- **A turn with no steps** (a one-line answer) leaves `[ STEPS ]` showing the most recent turn that had any, and says so in the label: `[ STEPS · TURN 1 ]` (scenario F.2). The pane does not go blank because you asked a quick question.
- **Site.** `Pane`; state from `turn.start`, `turn.step`, `tool.call`, `turn.complete`, and `Spinner`'s `mode` and `message` **(types)**.

### E.39 `[ STEPS ]` · new

**Purpose.** Every step of one turn: when, what kind, on what, with what result. Passing steps are quiet; exceptions carry a mark in the spine.

<<e-steps-72>>

<<e-steps-56>>

<<e-steps-40>>

- **Row.** Spine mark or blank; kind word (muted, 8 cells); subject (text); result, right-aligned, ending 2 cells before the time edge; the turn clock at which the step finished, dim, on the time edge. Read down the right edge and it is a timeline; read down the left edge and it is the exceptions.
- **Marks.** `✕` failed. `⊘` blocked by a system. `!` waiting on you. `✓` a check that passed after a failure, or the last check before the answer. `±` committed. `↗` published. `▍` you decided this step (denied it, answered it, cut it). `∴` thought. `▸` in progress. A passing step has no mark: 9 of 10 rows are plain grey text.
- **Result colour.** Muted by default. err and bold on a failed row, ok on a `✓` row, warn and bold on `⊘` and `!`, text on `±` and `↗` (a hash or a PR number you may want to read).
- **A step's two states.** A row appears when the step starts (`▸`, result `running`, subject bright) and changes once when it ends (mark, result, clock). After that it never changes. A step that takes less than 250 ms is drawn once, finished.
- **Label rule.** `[ STEPS ]`, then the count and, in err, the number that failed.

**How 300 steps fit.** The section is a window, not a scroll:

- If the steps fit, they are all shown, from the top, with blank rows under them.
- If they do not, the first row is `… n earlier`, followed by up to three kinds by count, in dim. Then come the **open exceptions**: failures and blocks that nothing has fixed yet, however old, at most 3 (if there are more, `✕ 5 open · s shows all`). Then the newest steps, as many as fit. The list scrolls by one each time a step starts, and the `… n earlier` row counts up.
- An exception leaves the pinned rows the moment a later step fixes it. So during a long turn the top of `[ STEPS ]` is a short list of what is still wrong. Usually it is empty.
- The first row never lies about what is hidden: its count and kinds cover exactly the rows that are not shown.

- **Narrow.** E.36's table. At 40 columns a marked row keeps its result and cuts its subject; an unmarked row keeps its subject and drops its result. The mark, the kind word and the clock survive to 40.
- **Site.** `Pane`; `tool.call` (the call, then its result after `next(e)`), `turn.step` **(types)**.

- **Row.** `◇` and the name in agent-lavender (22 cells, cut with `…`); the kind word and subject of the agent's current step; its step count and its elapsed time, dim, on the right.
- **States.** *Launched*: kind `start`, subject `reading its brief`, 0 steps. *Running*: as above, the subject changing with each step (at most once a second). *Done*: the glyph and name go muted, the kind slot says `done`, the subject becomes the head of its report (`4 findings`), the time freezes. *Failed*: `✕` in err, `failed` bold, the reason. A row never moves: agents stay in launch order, so you can find one by position.
- **Nested agents** are inset 2 cells under their parent. Two levels are shown; deeper ones are counted on the parent (`+2 nested`).
- **Seven agents** are seven rows. That is the section's cap; an eighth is `… 1 more`, and `a` shows all (E.44). A nested agent rides with its parent and does not count against the cap.
- **Label rule.** Failed first (in err), then running, then done, then nested: at 40 columns the meta loses fields from the right, and the failure is the one to keep.
- **Opening an agent.** Enter on a focused agent row switches the transcript to that agent's own conversation (`$.ui.view`, allowed only as the answer to your own key **(types)**). The pane stays, and its props say which agent is in view **(types)**: `[ STEPS ]` then lists that agent's steps and its label says `[ STEPS · AGENT Audit tests ]`. Enter again, or Escape at the prompt, returns to the main conversation.
- **After the turn.** The roster stays, frozen, until the next turn starts. Background agents that are still running keep their rows live and `[ LAST ]` says so.
- **Site.** `Pane`; `agent.spawn`, `agent.report`, and the `agentId` on `turn.step` and `tool.call` **(types)**.

### E.41 `[ TODO ]` · new

<<e-todo>>

<<e-todo-40>>

- **Row.** `[x]` done (muted), `[>]` in progress (text-bright, with `▸` in the spine), `[ ]` open (text). The label rule says `n of m`.
- **Window.** When the list is longer than the section's rows, it shows the item before the current one, the current one, and what follows. Finished items scroll out at the top; the count in the label accounts for them.
- **Rewritten list.** If Claude replaces the list (items added or removed, not just ticked), the section redraws and the label says `REVISED` until the next turn.
- **All done.** One row, `all 7 done`, until the next turn starts; then the section is absent.
- **Site.** `Pane`; `tool.call` on `TodoWrite`.

### E.42 `[ FILES ]` and the diff view · new

**Purpose.** What changed on disk this turn, and one keystroke to see how.

<<e-files>>

- **Row.** Path relative to the project root (cut in the middle, keeping the file name); a muted tag, `new`, `del` or `ren`; `+n` in ok and `−n` in err, right-aligned in two columns. In order of first change, so a row never moves; its numbers update when the file is edited again (at most once a second).
- **Scope.** The files this turn changed. Pinned: the files that turn changed. It is not the working tree: the status line has the uncommitted count.
- **Cap.** 4 rows (6 in a tall pane), the last being `… n more files · +a −b`. `f` shows all.

**How a diff is viewed.** Three ways, by where you are:

1. **In the pane.** Focus the pane, Tab to a file, Enter. The pane's body becomes the diff view:

<<e-diff>>

   Diff rows are on `surface`, coloured and signed as in E.8. A row longer than the pane wraps with `↩`. `n` and `p` move between hunks, `c` copies the file's patch to the clipboard (`$.ui.copy` **(types)**), `b` or Escape goes back. The view is as tall as the diff: the engine scrolls it with the arrows and the wheel **(types)**.

2. **On the left, on request.** `/diff hooks/register.tsx` prints the first hunk as a diff frame in the transcript, where it can be selected and where a 40-column pane cannot hurt it (scenario F.42). `/diff <path> all` prints every hunk.
3. **In the unfolded view.** ctrl+o shows each edit's diff under its step (E.4).

- **Site.** `Pane`; `tool.call` on the edit and write tools gives the patch; `ui.press` for Enter **(types)**.

### E.43 `[ SOURCES ]` · new

<<e-src-72>>

<<e-src-40>>

- **Row.** The answer's footnote mark in link-blue, or `·` in dim for a page that is not cited; the host in web-teal; the page title in text; the HTTP status on the right, dim, or err and bold when it is not 2xx.
- **Order.** Cited pages first, in mark order, once the answer exists. While the turn runs, pages appear in the order they were fetched, all with `·`. The reorder happens once, when the turn ends and `[ NOW ]` becomes `[ LAST ]`, which is the one moment the pane is allowed to rearrange.
- **Label rule.** `n read · m cited`.
- **No URLs here.** The full, clickable URL of a cited page is in the answer's `[ SOURCES ]` frame on the left (E.9). In the pane, `u` shows every page with its URL on a second row; Enter on one opens it in the browser, `c` copies it (scenario F.41).
- **Site.** `Pane`; `tool.call` on WebFetch and WebSearch; the marks from the final `AssistantMessage`.

### E.44 Focus, keyboard and scrolling · new

**Purpose.** Reach everything the pane holds without the mouse, and never trap a key.

- **Taking and returning the keyboard.** ctrl+x tab or a click gives the pane the keyboard; Escape returns it to the prompt; ctrl+x x closes the pane **(types)**. These are the engine's keys and Cockpit does not rebind them. While the pane has the keyboard its props say `isFocused` **(types)**: the divider turns rule-strong, the engine's row shows `pane`, and the hint line lists the keys (E.18).
- **Moving.** Tab walks the pane's rows that can be opened; the arrows scroll **(types)**. The engine inverts the row that holds the focus ring; the mocks show it on `chip`.
- **Cockpit's keys** are single lower-case letters, which is the only kind a pane may bind **(types)**, and they act only while the pane has the keyboard:

| Key | Does |
|---|---|
| `s` | `[ STEPS ]`: fitted ↔ full view |
| `a` `t` `f` `u` | show all of `[ AGENTS ]`, `[ TODO ]`, `[ FILES ]`, `[ SOURCES ]`; again to fit |
| `p` `n` | pin the previous / next turn (E.45) |
| `l` | live: release the pin |
| enter | open the focused row: a step's detail, a file's diff, an agent's conversation, a source's page |
| `c` | copy the focused row as text (a step's command, a path, a URL, a patch) |
| `b` | back from a detail view |

- **From the prompt**, without focusing: `/steps`, `/diff`, `/files`, `/copy` (E.24).

**The full view.** `s` replaces the fitted layout with the whole step log of the turn: every sentence Claude said (`│` rows) and every step under it, exactly the rows of the unfolded view (E.4), 300 steps and all. The tree is now taller than the pane, and the engine scrolls it **(types)**:

<<e-full>>

- The engine follows the end of a tree that is growing, and holds its place once you have scrolled up (**probe 21**). The label says which rows are showing.
- `[ NOW ]` is not pinned in the full view: the engine scrolls the whole tree. The left now-row still says the turn is alive.
- Escape, or `s` again, returns to the fitted layout.

**A step's detail.** Enter on a step:

<<e-detail>>

- The full command, how long the step itself took, its exit, and the last rows of its output on `surface` (the first rows on success). `c` copies the output, `r` the command.
- **Site.** `Pane` (`isFocused`, `scroll`); `Button` with `hotkey` and `autoFocus`; `ui.press`, `ui.focus`, `ui.scroll`; `$.ui.scroll`, `$.ui.focus`, `$.ui.copy` **(types)**.

### E.45 History: pinning a past turn · new

**Purpose.** The pane shows the current turn, but people scroll back. Pinning puts an earlier turn's steps in the pane without losing sight of the live one.

<<e-pin>>

- **How to pin.** `/steps 7` from the prompt; or, with the pane focused, `p` and `n` to step back and forward through the turns; or a click on turn 7's receipt, if receipts can be buttons (probe 25). The receipt is where the number comes from: every turn leaves `· turn n` on the left.
- **What changes.** `[ STEPS ]`, `[ FILES ]` and `[ SOURCES ]` show the pinned turn, and each says so in its label: `[ STEPS · TURN 7 · PINNED ]` in text-bright, `[ FILES · TURN 7 ]`. The step section's meta adds the pinned turn's duration.
- **What does not change.** `[ NOW ]`, `[ AGENTS ]` and `[ TODO ]` stay live. A pinned pane can never hide that Claude is working, waiting on you, or done: the head is always the present.
- **Releasing.** `/steps` with no number, `l` in the pane, or sending a prompt. A pin is for reading; your next prompt means you have moved on. Pinning the current turn is the same as releasing.
- **What is kept.** A step log per turn: for each step its kind, subject (cut at 200 characters), result, mark and clock; the sentences; the files and sources. Output and diffs are not kept: the detail and diff views read them from the session while it has them, and say `output no longer held · ctrl+o` when it does not. Logs live in the session's state and survive a plugin reload **(types)**; the last 50 turns are also written to the plugin's store so they survive a resume (**probe 24** for its size limit).
- **After a compaction** the logs are intact: they are the plugin's data, not Claude's context. A turn from before the compaction says `· before the compaction` in `[ LAST ]`, because Claude no longer remembers its steps even though you can still read them.
- **After a resume** the head is `[ LAST ]` with the last turn of the earlier session, restored from the store, and `/steps n` works for every turn that has a log (scenario F.43).
- **No log** (a turn older than the 50 kept, or a session begun without the plugin): `/steps 3` answers `no step log for turn 3 · ctrl+o shows what the session still has`.
- **Site.** `command.run`; `$.state`, `$.store`; `Pane`.

### E.46 The inline inspector · new

**Purpose.** Where no dock exists, the step log is still one command away. `/steps 7` opens the same pane; the engine seats it inline, above the prompt **(types)**.

<<e-inline>>

- **What it shows.** One section: `[ STEPS · TURN n · PINNED ]`, fitted to the rows the engine gives (Cockpit asks for 12 with `rows`; the engine grants up to what the layout spares **(types)**). It runs the full width of the terminal, so results and clocks have room. The same keys work: `s` for the full view, Enter for a step's detail, `p` and `n` for other turns.
- **It is asked for, never automatic.** In fallback Cockpit does not open a pane on its own: an inline block above the prompt would push the conversation up, which is the opposite of what fallback is for. It opens with the keyboard (`focus: true`) and `closeOnEscape`, so Escape both returns the keys and closes it **(types)**.
- **`/steps` with no number**, in fallback, opens it on the current turn, live.
- **Site.** `Pane` with `placement: "inline"`; `$.ui.open({ id, focus, closeOnEscape, rows })` from `command.run` **(types)**.

### E.47 Mode switching · new

**Purpose.** One session can pass through all three modes. Each switch has one rule.

| From → to | Trigger | What happens |
|---|---|---|
| start → docked | fullscreen and `C ≥ 144` (or `≥ 110` after `/cockpit`) | the open is placed with `placement: "dock"`; the transcript draws without capsules |
| start → fallback | not fullscreen, or too narrow | the open is not placed, or is seated inline and closed; capsules and the full live area |
| docked → fallback | the window narrows below the threshold | the engine un-docks the pane (**probe 18**: it either reports it unplaced or reseats it inline; Cockpit closes an inline pane it did not get asked for). In fullscreen the engine then redraws every visible row at the new width, and each row is drawn in fallback style: finished turns gain their capsule, the running turn's work moves to the live area |
| fallback → docked | the window widens past the threshold | Cockpit opens the pane again after the width has been stable for 300 ms, so a drag across the threshold does not flap. Rows are redrawn without capsules; the pane has the whole step log because the log never stopped |
| either → the other, by `/tui` | fullscreen turned on or off | the terminal's layout is fixed for a session's lifetime in the types, so the switch is expected to restart the surface (**probe 19**). State survives in `$.state`. Rows already in the main screen's scrollback stay as printed |
| any → pane closed by hand | ctrl+x x, the close mark, `/cockpit off` | fallback for the rest of the session; `/cockpit` reopens. The engine also forgets that you asked for the pane, so below 144 columns it will not come back on its own **(types)** |

- **Why a mixed scrollback is still readable.** On the main screen, rows cannot be redrawn. A turn printed while docked has no capsule, and one printed in fallback has. Both end in a receipt that names the turn and its exceptions, and the docked receipt carries the step count itself. No turn is left without its numbers, whichever mode drew it.
- **What never happens on a switch:** a row is lost, a count changes, or the pane opens on top of the conversation unasked.
