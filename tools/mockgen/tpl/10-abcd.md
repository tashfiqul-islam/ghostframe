# Cockpit: the ghostframe chat interface, v7

> History: Cockpit's first written spec, generated by tools/mockgen and kept byte for byte. Superseded by `docs/design/cockpit.md`.

Design specification for the Claude Code transcript and its docked pane in a terminal. Target: Windows Terminal, Geist Mono Nerd Font 11.5pt, truecolor, background `#0B0B0E`, 60 to 240 columns. Checked against the plugin API types shipped with Claude Code 2.1.329 (`claude-code.d.ts`; v6 was checked against 2.1.328, and every v6 claim reused here was checked again). A claim that comes from those types is marked **(types)**. Everything that still needs a run in a real session is marked **probe n** and collected in section I.

How to read the mocks: every `text` block is exactly the stated width in cells. Hero mocks carry a `paint` block (one token letter per cell, capital = bold, space = blank cell) and a `bg` block (`.` base, `s` surface, `z` zebra, `k` chip). All mocks were generated by a script that fails on any line that is not exactly the stated width, and on any glyph that is not in table D.3. The pane inside every screen mock is not drawn by hand: it is the output of the layout rule in E.37, run on that scenario's data.

Three words are used throughout:

- **docked**: fullscreen mode, the pane sits beside the transcript.
- **inline**: the pane sits above the prompt, because you asked for it where no dock exists.
- **fallback**: no pane. The transcript carries the work as capsules.

---

## A. Thesis

Cockpit splits the screen the way an IDE does, by kind of attention. The left half is a conversation and nothing else: your prompts, Claude's answers, the few things you must act on, the few things that left your machine, and one receipt per turn. The right half is an instrument: what Claude is doing this second, every step of the turn with its result, the agents, the plan, the files and the sources. The left is append-only and you read it. The right changes freely and you glance at it. A 300-step turn costs the left side one receipt row and costs the right side nothing it has not already reserved.

The two halves are one instrument because they share one grid. Each has a spine in its column 0, a blank gutter, content from column 2, and a time edge on its last column. Each uses the same glyphs, the same kind words, the same state words and the same clock format. A row that moves from the pane to the transcript (when the window gets narrow, or when you print a step log) does not change shape.

The pane is a convenience and never a dependency. Every fact in it can also be reached as text (ctrl+o, `/steps 7 all`), nothing that needs you is ever shown only there, and when no dock exists the same facts fold into one **capsule** row per stretch of work, plus a row for each exception. That fallback is designed as carefully as the docked view, because it is what you get in tmux, below 110 columns, and outside fullscreen.

## B. Principles

| # | Rule | Test a developer can run |
|---|---|---|
| 1 | **One spine, twice.** In each half, column 0 holds at most one glyph, column 1 is blank, text starts in column 2. | Regex every drawn row of the transcript, and every row of the pane body, against `^(.\| ) ` (or an indent of 2n spaces); zero failures. |
| 2 | **The left is a conversation.** A transcript row is one of five things: your words, Claude's words, something you must act on, something that left the machine, a receipt. A step is none of these. | Run 50 passing `Read` calls docked: the transcript grows by 0 rows; the pane's `[ STEPS ]` count grows by 50. |
| 3 | **The right is an instrument.** It shows state. Nothing exists only there. | Close the pane mid-turn (ctrl+x x). Every count and every failure is still reachable: receipt, capsule, ctrl+o, `/steps n all`. |
| 4 | **Append-only left, calm right.** Rows above the newest transcript block never change. The pane changes, but its sections never move during a turn, its rows never reorder, and it never animates. | Record a turn at 30 fps. Left: only appended rows differ. Right: no section label changes its row between `turn.start` and `turn.complete`, unless a section appears for the first time. |
| 5 | **Time lives on the right edge of each half.** Durations and clocks are right-aligned to the last column of their half and nowhere else in a row. | The last non-blank cell of every receipt, turn rule, capsule and step row is in the last column of its half. |
| 6 | **Words carry meaning, colour confirms it.** Every state is a word, every row kind a distinct glyph. | Render with `NO_COLOR=1`; every state in section E is still distinguishable in a screenshot of either half. |
| 7 | **One glyph, one meaning, both halves.** No glyph in table D has a second purpose, and the pane uses no glyph the transcript does not. | Grep the source for each glyph; every use maps to its row in table D. |
| 8 | **No walls.** Frames and sections have a top rule and nothing at their sides. The only vertical line on screen is the engine's divider between the halves. | Mouse-select a code block and paste: the result differs from the source only by a uniform 2-space indent. |
| 9 | **Colour is rationed.** Accent is only for you. Green, pink and amber only for a result. Lavender only for agents, teal only for web hosts, blue only for URLs. | Screenshot a 20-step passing turn, docked: the only non-grey cells are the accent bar, the cursor and the spinner. |
| 10 | **Say it once.** A fact has one home on screen. The step in progress is in the pane, the turn clock is on the left, the model is in the status line. | Search a docked screenshot for any number or name; it appears once outside the prose. |
| 11 | **Same turn, every mode.** Docked, inline and fallback show the same facts. Only the place changes. | Resize 200 → 100 mid-turn: every count the pane showed is now in a capsule, the live area or a receipt. Resize back: the reverse. |
| 12 | **Nothing that needs you is only in the pane.** Permissions, questions, plans, limits and failures that were never fixed reach you on the left or at the prompt. | Close the pane and run section F's scenarios 9, 12, 14, 19 and 37: you are stopped, and told why, in each. |

## C. Grid

### C.1 Columns

Let `C` be the terminal width in cells. When a pane is docked it takes `P` body cells plus a 2-cell chrome that the engine draws (a divider and a pad: **probe 17**). The transcript's region is `L = C − P − 2` cells, or `C` when nothing is docked. The frame is `F = min(L − 1, 120)`; the last column of the region stays empty. All positions are 0-based, and the pane's positions are relative to its own body.

| Name | Transcript | Pane | Notes |
|---|---|---|---|
| spine | column 0 | column 0 | one glyph or blank |
| gutter | column 1 | column 1 | always blank |
| content | columns 2 … F−1 | columns 2 … P−1 | |
| prose measure | columns 2 … min(F−1, 89) | — | at most 88 cells; the pane holds no prose |
| time edge | ends at F−1, 7 cells + 1 gap | ends at P−1, 7 cells + 2 gap | `59m 59s` is the longest clock |
| result | — | ends 2 cells before the time edge | right-aligned, at most 16 cells |
| rule | columns 0 … F−1 | columns 0 … P−1 | turn rules, frame rules, section rules start on the spine |
| inset | +2 per level | +2 per level | nested list, nested agent, detail row |
| live area | columns 0 … F−1 docked, 0 … C−6 otherwise | — | undocked, the band loses 5 cells to the engine's `[-]` mark **(types)** |

How wide the pane is. Cockpit asks the engine for the widest of 72, 56 or 40 body columns that still leaves the transcript 100 cells, with `$.ui.open({ columns })`. The engine grants at most 45% of the terminal and at least 24, and a width you dragged the dock to wins over the request **(types)**. So the pane must draw at any width from 24 to 90; 40, 56 and 72 are the three it is designed at, and the row formats in E.39 to E.43 say what gives way between them.

| C | mode | P | L | F | prose | notes |
|---|---|---|---|---|---|---|
| 60 | fallback | — | 60 | 59 | 57 | capsules name two kinds instead of three |
| 80 | fallback | — | 80 | 79 | 77 | |
| 100 | fallback | — | 100 | 99 | 88 | |
| 110 | docked only if you asked once | 40 | 68 | 67 | 65 | the engine docks from 110 only for a pane you opened yourself **(types)** |
| 144 | docked | 40 | 102 | 101 | 88 | the engine docks an unasked pane from 144 **(types)** |
| 160 | docked | 56 | 102 | 101 | 88 | |
| 200 | docked | 72 | 126 | 120 | 88 | the hero width |
| 240 | docked | 72 | 166 | 120 | 88 | the transcript does not widen past 120; the pane does not widen past 72 unless you drag it |

Rules that follow from the table:

- The transcript never centres and never gains a left margin. Engine rows start at column 0, so a margin would create a second grid.
- From `F ≥ 99`, prose stops at column 89 and the last cells of the frame hold only time and meta: the meta margin.
- Outside fullscreen there is no dock at any width: the engine seats a pane inline above the prompt **(types)**. Cockpit does not open one there unasked; it uses the fallback, and `/steps` opens the inline inspector (E.46).
- Between 110 and 143 columns the pane docks only after you have opened it once with `/cockpit`; the engine remembers that until you close the pane by hand **(types)**.

### C.2 Vertical rhythm

Blank rows between a block (row heading) and the block that follows it (column heading) in the transcript. `·` means the pair cannot occur.

| above ↓ / below → | turn rule | prompt | capsule or event row | prose | frame | receipt | engine row |
|---|---|---|---|---|---|---|---|
| **turn rule** | · | 1 | · | · | · | · | 1 |
| **prompt** | · | 0 | 1 | 1 | 1 | 1 | 1 |
| **capsule or event row** | · | 1 | 0 | 1 | 1 | 1 | 0 or 1, engine-owned |
| **prose** | · | 1 | 1 | 1 | 1 | 1 | 1 |
| **frame** | · | 1 | 1 | 1 | 1 | 1 | 1 |
| **receipt** | 2 | · | · | · | · | · | 1 |
| **engine row** | 2 | 1 | 1 | 1 | 1 | 1 | 0 |

Inside blocks: a frame's label rule, content and closing rule touch. A heading has 1 blank above (2 for a first-level heading) and 0 below. List items touch. The live area is separated from the transcript by exactly 1 blank row, and from the prompt by 0. The only 2 in the matrix is the gap before a turn rule: the widest space on screen always means "a new turn".

In the pane: a section's label rule and its rows touch. Sections are separated by 1 blank row when the pane has 24 body rows or more, and by none below that. The pane's first body row and the transcript's first row are the same terminal row, so the two halves share every baseline; there is no half-row offset anywhere.

## D. Tokens

### D.1 Colour

Unchanged from v6, including both contrast fixes. No token was added for the pane.

| Token | Paint | Value | Contrast on bg | Used for |
|---|---|---|---|---|
| bg | `.` | `#0B0B0E` | — | base, in both halves |
| surface | `s` | `#13131A` | — | prompt rows, code rows, diff rows in the pane |
| chip | `k` | `#1E1E26` | — | inline code, the selected option, the focused row of the pane |
| zebra | `z` | `#0F0F13` | — | every second table row |
| hairline | `h` | `#2C2C36` | 1.4:1 | rules, the divider |
| rule-strong | `H` | `#3A3A48` | 1.8:1 | the capsule bar, the table header rule, the divider while the pane has the keyboard |
| text | `t` | `#B2B2BC` | 9.3:1 | answer prose, event rows, step subjects |
| text-bright | `b` | `#ECECF1` | 16.7:1 | your prompt, lead sentence, headings, the step in progress |
| muted | `m` | `#7C7C88` (v5: `#686874`) | 4.8:1 | capsule text, kind words, labels, meta |
| dim | `d` | `#5E5E6A` (v5: `#4E4E5A`) | 3.1:1 | clocks, frame brackets, hints, the `… n earlier` row |
| accent | `a` | `#FAB387` | 11.1:1 | you: the prompt bar, your decisions, the cursor, the spinner |
| link | `l` | `#8FB8DE` | 9.4:1 | URLs and footnote marks |
| ok | `g` | `#96D292` | 11.2:1 | a check that passed, added lines |
| warn | `w` | `#E8B98A` | 11.0:1 | needs you, blocked, limits |
| err | `r` | `#EC84A0` | 7.8:1 | failed, removed lines |
| agent | `v` | `#B4A0DE` | 8.4:1 | agent names |
| web | `c` | `#7EC8BE` | 10.2:1 | web hosts |

`muted` now carries more than it did in v6 (every kind word and most of a 40-column pane), and it was already raised to AA for body text for that reason. `dim` carries every clock on both time edges, at the 3:1 floor. `warn` and `accent` stay close in hue and apart in role: accent is a bar, a cursor or the spinner; warn is always a word. Probe 14 still decides whether `warn` moves to `#E5C07B`.

### D.3 Glyphs

Spine glyphs (column 0 of either half):

| Glyph | Code point | One meaning | Left | Right | Drawn by |
|---|---|---|---|---|---|
| `▍` | U+258D | you: a prompt, a steer, a decision you made | prompt and decision rows | a step you decided (`denied`, an answer, a plan verdict, `cut`) | plugin |
| `│` | U+2502 | the rail: work, folded | the capsule (fallback); a sentence Claude said while working (unfolded view) | a sentence Claude said while working (full view) | plugin |
| `✕` | U+2715 | failed | a failure that was never fixed; any failure, in fallback | the step that failed; an agent that failed | plugin |
| `⊘` | U+2298 | blocked by a system (classifier, hook, sandbox, policy) | a block that was never resolved; any block, in fallback | the step that was blocked | plugin |
| `!` | U+0021 | needs you: the turn cannot continue without you | limits, context | the step that is waiting on you; the `[ NOW ]` row | plugin |
| `✓` | U+2713 | a check passed (tests, types, CI) | fallback only | the check that passed after a failure, or the last check before the answer | plugin |
| `↗` | U+2197 | published outward (push, pull request, merge, release) | always, at once | the step that did it | plugin |
| `±` | U+00B1 | a recorded change (commit) | — | the step that committed | plugin |
| `↺` | U+21BA | rewound to a checkpoint | the rewind row | — | plugin |
| `◇` | U+25C7 | an agent | engine rows; the fallback roster | the roster | engine and plugin |
| `●` | U+25CF | a notice from outside the turn | notices | — | engine and plugin |
| `›` | U+203A | a message from an agent (engine) | engine row | — | engine |
| `※` | U+203B | a recap (engine) | engine row | — | engine |
| `∴` | U+2234 | thought | unfolded view | a `thought` row in `[ STEPS ]` | plugin |
| `▸` | U+25B8 | the current item of a list | the selected option, the current to-do (fallback band) | the step in progress, the current to-do, the `[ NOW ]` sentence | plugin |
| `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | U+280B… | running, now | the live now-row only | never | plugin |

`▸` moved from the inline table to the spine table: in the pane it sits in column 0, and "the step in progress" is the current item of the step list, which is the meaning it always had. The spinner stays out of the pane on purpose (principle 4).

Inline glyphs:

| Glyph | One meaning |
|---|---|
| `─` | a turn boundary (solid rule): the opening rule and the receipt |
| `┄` | a frame or section boundary (dotted rule) |
| `[ ]` around capitals | the label of a rule |
| `·` | separator between fields of one row; an uncited source |
| `…` | text was cut here; `… n earlier`, `… n more` |
| `↩` | this row continues an unbreakable token from the row above |
| `→` | becomes (before → after, question → answer, failure → fixed) |
| `▰` `▱` | one filled / one empty cell of a meter (status line only) |
| `▏` | a quotation |
| `¹ ² ³` | a footnote mark, in the answer and beside the same source in the pane |
| `[ ]` `[x]` `[>]` | to-do: open, done, in progress |
| `+` `-` at column 2 of a diff | added line, removed line |
| `−` (U+2212) | a negative number, removed-line counts |
| `█` | the text cursor |
| `[×]` | stand-in for the engine's close mark on the dock (**probe 17** for its real look) |

Nerd Font private-use icons are still not used anywhere in the transcript or the pane: they do not survive copy and paste, and each needs a word beside it anyway. **The status line keeps its Nerd Font icons** (E.35): nothing there is ever copied, and the script already owns that look.

Kind words (the fixed vocabulary for a step; always lower case, always muted, at most 8 cells): `read` `edit` `write` `search` `shell` `test` `web` `fetch` `mcp` `skill` `hook` `notebook` `browser` `agent` `ask` `plan` `todo`. Three more appear only in `[ NOW ]`, where no tool is running: `thinking` `writing` `waiting`.

State words (the fixed vocabulary for a result): `done` `failed` `blocked` `denied` `needs you` `interrupted` `waiting` `running` `queued` `skipped`. Two compounds are built from them and used only on the left: `still failing`, `still blocked` (E.5).
