# Cockpit v7: feasibility

What the probes of [cockpit-v7.md](cockpit-v7.md) section I.4 found, what each finding means for every component, and the order to build in. Read [cockpit-v7-amendments.md](cockpit-v7-amendments.md) first: it overrides the spec.

## How the probes were run

- **When and what:** 2026-11-21, Claude Code 2.1.329, model Haiku 5.5, Windows 11.
- **Session:** a real interactive session in fullscreen, 200 × 50 (a second one started at 120 × 50), launched as `claude --plugin-dir <probe mod> --settings <override> --debug-file <log> --model haiku`. The override set `"tui": "fullscreen"`, emptied `CLAUDE_CODE_PLUGIN_DIRS` and disabled every installed plugin, so the probe mod was the only plugin loaded (debug log: `Loaded 1 directory-loaded plugins`).
- **Terminal:** a Windows pseudo-console (ConPTY, through `pywinpty`), with the `pyte` terminal emulator keeping a copy of the screen. Keys, mouse events and resizes were sent as bytes; the screen was read back as text; every byte the session wrote was kept with its time.
- **Probe mod:** one throwaway hooks module, `cockpit-probe`, on branch `probe/cockpit-v7` in its own worktree. It logged every event and every `ui.render` raise to a JSON-lines file, and a `/probe` command switched behaviours between turns. The branch, the worktree and the module are deleted. `main` was never touched.
- **Limits of this setup.** It is not Windows Terminal: nothing here says anything about fonts, glyph widths or how colours look. Probes that need eyes on the real terminal are marked **not run**. Every turn was short (under 15 seconds, at most 3 tool calls), so nothing here measures a 300-step turn.

## Probes

Verdicts: **passes**, **fails**, **partial**, **not run**.

### The seven that decide the architecture

**Probe 1: can narration leave the transcript once a tool call follows it?** Passes.

- Ran: a hook on `AssistantMessage` that reads an atom and returns an empty `<Box />` for a block marked as narration; a `tool.call` hook that marks the last drawn block and writes the atom. Prompt: say a sentence, read a file, three times, then answer.
- Evidence: without the flag the screen held `● I'll read a.txt first.` / `Read 1 file` / … / the answer. With it, the finished turn was the prompt, one blank row, the answer, the receipt: 0 rows and 0 blank rows where three narration blocks and three tool groups had been. The log shows each block raised again within 0.1 s of the atom write (`folded: false` at 76.27 s, `tool.call` at 76.71 s, `folded: true` at 76.81 s).
- Also found: a block is raised once, complete; text does not stream into the transcript (correction E). In every case the tool group's first raise and the spinner's `tool-input` mode arrived in the same frame as the narration block (30.56 s and 30.57 s), and the final block of a turn was raised after `turn.complete`. So the plugin can know what a block is before it draws it for the first time, and the narration need not flash.
- Not seen: an `isSummary` block. The turns were too short to produce one.
- Fallback: none needed.

**The pane: opening, docking, and live updates at about one per second without flicker.** Passes.

- Ran: `$.ui.open({ id, columns: 72 })` at `session.start`; a pane that draws a ruler and a counter; `tool.call` writing an atom; then `$.clock.every(250)` and `every(1000)` writing it, with the raw output measured between marks.
- Evidence, placement: `{ isPlaced: true }`; props `placement: "dock"`, `bodyColumns: 72`, `scroll.bodyRows: 42`, `viewport: { columns: 127, rows: 50, isFullscreen: true }`. The divider is one column (index 127), the body starts at 128, the engine's close mark `✕` is at the right end of the dock's first row, and the pane ends above the prompt box.
- Evidence, live updates: the counter went 0 → 3 during a turn with 3 tool calls. At 4 updates per second for 8.1 s the terminal received 2,706 bytes in 33 frames, each one wrapped in synchronized output (`ESC[?2026h` … `ESC[?2026l`), each writing only the cells that changed (`ESC[134C ESC[2B … 5 ESC[143G 60 ESC[172G 960`): about 82 bytes per update, no screen clear, no cell of the transcript rewritten. At 1 per second: 812 bytes in 9 frames. Idle for 6.1 s: 0 bytes.
- Evidence, thresholds (second session, a pane id never opened before): at 120 columns the unasked open answered `{ isPlaced: false, reason: "unasked below 144 columns (120 now): placed when the person opens it, or when the terminal is widened to 144 columns" }`. Widening to 143: nothing. To 144: docked by itself, body 63. Back to 120: stayed docked, body 53. `/probe open 40` at 120: docked, body 40. At 110: docked. At 109: `placement: "inline"`, body 105. At 200 again: docked.
- Fallback: none needed. "Without flicker" is shown by the bytes; it was not watched on a real monitor.

**Pane scrolling.** Passes.

- Ran: a pane tree of 1,302 rows in a 42-row body; five wheel-down events over the pane; `$.ui.scroll({ in, to: "end" })`; one row appended per second while at the end; three wheel-up events, then four more seconds of appending.
- Evidence: first row shown went 1 → 11 after five notches (2 rows per notch, with the pane not focused). After the scroll call the body showed rows 1259 to 1300 and the props read `offset: 1260`. While rows were appended the offset followed: 1261, 1262 … 1266, one per second. After scrolling up, the body stayed on 1259 to 1300 while the tree kept growing.
- Fallback: none needed. Nothing is sticky: the first rows of the tree scroll away with the rest, as E.44 assumed.

**Zero-row tool steps in the transcript.** Passes.

- Ran: an empty `<Box />` for every `ToolGroup`, `ToolUse` and `ToolResult` that had not errored and was not expanded.
- Evidence: see probe 1: three reads left no row and no blank row. Every folded call arrived as a `ToolGroup` (correction F).
- Not covered: a call that errors inside a group with others. A refused call arrived as a group with `isCallsOnly: false`.
- Fallback: none needed.

**`TurnDuration` on every turn.** Partial.

- Ran: logged every raise; returned a 5-row tree with a `Button` in it; clicked the button with a mouse event.
- Evidence, raised: a 3-tool turn (6,586 ms), a prose-only turn (1,112 ms), a turn started by a `!` command, a turn that waited at a permission dialog (2,485 ms: the wait is not counted), a turn left waiting on background agents (`waitingFor: { agents: [2 entries] }`), and the turn that followed their reports.
- Evidence, not raised: an interrupted turn (Esc while the answer was being written) and a turn that ended on a refusal at the dialog. The engine drew `⎿ Interrupted · What should Claude do instead?`, and no site was raised for that row.
- Evidence, tree: all 5 rows drew, directly under the answer with no blank row between (the engine adds none when a hook draws the tree). The click logged `receipt.pressed`.
- Fallback: correction G. An interrupted turn has no receipt; `turn.complete` carries `isAborted`, so `[ LAST ]` can still say it.

**Agent notices arriving as `UserMessage`.** Passes.

- Ran: a turn that launched two background agents; logged `UserMessage`, `ToolUse`, `agent.spawn`, `agent.report`, and every site.
- Evidence: a finished agent is a `UserMessage` with `origin: { kind: "task-notification" }` and `task: { id, status: "completed", toolUseId, durationMs: 3710 }`. A message from an agent is a `UserMessage` with `origin: { kind: "peer" }` and `from: { name: "Explore" }`. Each launch is a `ToolUse` whose `tool` is `Agent`. `agent.spawn` gives `description`, `subagentType`, `background`; `agent.report` gives `agentId`, `status`, `text`. An agent's own calls arrive at `tool.call` with its `agentId`. A site named `AgentRow` is raised per agent and refreshed every 5 seconds.
- Not tried: drawing those `UserMessage` rows as nothing. They are ordinary raises of a site the plugin already draws, so the same empty tree should apply; that is an inference.
- Fallback: none needed.

**`$.ui.copy`.** Passes.

- Ran: `await $.ui.copy({ text: "cockpit-probe-copy-<time>" })` from a command, then `Get-Clipboard`.
- Evidence: the call answered `{ isCopied: true }` and the clipboard held `cockpit-probe-copy-1795212449280`. The clipboard's earlier content was saved first and put back.
- Fallback: none needed.

Still to probe before the phase that needs it: probe 4 (phase 4, in a repo with rules), probe 9 (phase 4), probes 13, 14 and 16 (phase 1, in Windows Terminal), probe 19 (phase 10), Tab and hotkeys in a focused pane (phase 7).

Probed in phase 5 (Claude Code 2.1.330, 200 × 50, docked): an empty tree for an agent's `UserMessage` row (its `peer` message, `from` the agent's type) draws no row and leaves no blank row.
