## How the KB numbers were made

- **ref** = the designer's reference script, minified with `bunx esbuild --minify` (esbuild 0.28.2), `gzip -9`.
- **sketch** = a hand-written vanilla TS version written for this inventory, complete enough to ship (keyboard,
  URL mirror, reduced motion, error path), in `scratchpad\try\inventory\src\*.ts`, bundled
  `esbuild --bundle --minify --format=esm --target=es2022`, `gzip -9`. Outputs in `...\inventory\out\`.
- Sizes are per piece; shared helpers (`calm.ts`, `decode.ts`, `tabs.ts`) are counted once in the page bundles.
- **est** = estimate, not measured.

## Notes

### Does anything need a component framework's reactivity?

No. Every piece is one of: CSS only; a pointer handler writing `style.transform`; an IntersectionObserver setting
an attribute; or a button toggling `hidden` / `aria-*`. The most state any piece holds:

- **Demo player:** one integer (`pos`), one boolean (`paused`), one tab id. The DOM is fixed and pre-rendered at build
  time from `session.ts`; each tick toggles `data-shown` on at most one element and rewrites two short text nodes.
  No list is ever re-rendered, nothing is created or removed. 1.25 KB gz including the shared tabs code.
  Re-rendering it in Preact would ship 5.7 KB of runtime, and as an Astro island it also serialises the session
  props into the HTML, so the data is in the page twice.
- **Release filters:** one string key. Toggling `hidden` on 4–5 group containers per version. Counts, groups and
  rows are build-time. Growth (more versions) adds DOM, not logic: still one `querySelectorAll`. 0.74 KB gz
  with the rail, `f` and the picker.
- **Status slider:** one number to one `data-state`; CSS does every colour. 0.44 KB gz.

Shared state across many nodes exists only for the eye state (numeral, tile, corners, ghost eyes, mascot), and CSS
custom properties plus one `data-state` attribute on a common ancestor carry it with no JS fan-out.

### Where a framework would be markedly easier

- **Demo, only if its scope changes**: if the demo ever renders different sessions on the client, lets the user
  scrub the timeline, or makes Sources/Todo/Agents change per step, a template layer helps. Preact (5.7 KB) is the
  cheapest. For the drawn design (one scripted turn, fixed end state), no.
- **Nothing else.** Tabs, accordion, sheet, slider: the platform gives the a11y semantics shadcn/Base UI wraps
  (`<dialog>` focus trap and Esc, `<details>`, native range keyboard). React + ReactDOM alone measured 68.9 KB gz.
  That fits under the 120 KB ceiling, but it is 5.7× everything the site needs.

### Risks to resolve

1. **WCAG 2.1.4 Character Key Shortcuts (A)**: the bare `f` shortcut needs a way to turn it off or remap it, or it
   must work only while the release page's filter region has focus. This is a user-owned decision. My recommendation:
   keep `f`, and let the motion switch's footer row offer "keyboard shortcut · on/off" (stored), or drop it.
2. **WCAG 2.2.2 without JS**: with scripts off, the CSS loops (eye slip, echo, scan band, carets) run and the
   ambient switch can't. Fix in CSS: gate every loop on `html[data-motion="on"]`, which only the inline script
   sets. No JS means no loops.
3. **Boot curtain without JS** must never cover the page: show it only when the inline gate ran (same attribute
   pattern).
4. **Accordion "none from keyboard"** via `:focus-visible` is a heuristic; spike it in Chrome, Firefox, Safari.
5. **Footer light on touch**: `pointermove` stops once the browser starts scrolling (`pointercancel`), so "follows
   your thumb" works only for taps and short drags unless the footer sets `touch-action`, which would block scroll.
6. **Travelling frame** in browsers without scroll-driven animations: the static frames are the baseline (HANDOFF).
   The 0.65 KB JS fallback is optional; I'd skip it (`shortcut:` static frames, until analytics show a need).
7. Tooltip appears only on the component sheet; if no page uses it, don't build it.
