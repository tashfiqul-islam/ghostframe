## What typescript@7.0.2 is

- Binary is **`tsc`** (package.json `bin: {"tsc": "./bin/tsc"}`), native Go build via `@typescript/typescript-<platform>` optional deps. `tsgo` was the name of the `@typescript/native-preview` beta only. Ran: `tsc --version` → `Version 7.0.2`.
- Main export `"."` is only `lib/version.cjs` (version string). It also ships `typescript/unstable/{sync,async,fs,ast,...}` exports — undocumented, unstable. No `lib/typescript.js` / `tsserverlibrary.js`, so anything that does `require("typescript")` for the classic API breaks.
- TS 7.0 blog (2026-07-08, <https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/>): "it does not ship with an API"; "We expect TypeScript 7.1 to ship with a new (and different) API"; run side by side with 6.0 via `@typescript/typescript6` (bin `tsc6`); Vue/MDX/Astro/Svelte "likely can't use TypeScript 7 yet" because Volar needs the programmatic API.
- TS 7.1 beta blog (2026-10-20, <https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/>): adds `contentMappers` in tsconfig + required `--runExternalCode`; Astro, Svelte, Vue mappers prototyped; new API split into `typescript/sync`, `/async`, `/fs`, `/ast`; RC "in about a month", final "shortly thereafter". Content mappers PR: microsoft/TypeScript#63936, merged 2026-08-21.

## What tsrs is

- npm `tsrs`, repo `oxc-project/tsrs` (the Oxc team; announced on the Cloudflare blog, linked from the README). README: "a drop-in replacement for the TypeScript 7 compiler and language server, written in Rust", aiming at "a stable version against TypeScript 7.1 with 100% conformance".
- Versions name the TypeScript release they port: `7.1.0-beta.tsrs5` = TypeScript **7.1.0-beta** semantics, tsrs revision 5 (`tsrs --version` → `Version 7.1.0-beta (tsrs 7.1.0-beta.tsrs2, microsoft/TypeScript@3e9236361fa9)`). So tsrs is **not** 7.0.2: it already has 7.1 features (content mappers). It also ships `tsrs-lint`, which oxlint ≥1.92 uses instead of oxlint-tsgolint when tsrs is installed.
- docs/COMPATIBILITY.md (repo main, read 2026-11-28 via `gh search code`): content mappers supported for `.vue/.svelte/.astro`; the linter "reports type errors in mapped files at their original ranges and does not run rules on them; oxlint sends no mapped files". SECURITY.md says the tsrs language server "does not currently start content mappers" while COMPATIBILITY.md says the LSP transforms mapped files — conflicting; treat tsrs editor support for `.astro` as unverified.

## Cleanest setup

Two honest choices; 7.0.2 alone cannot type-check `.astro`.

**Recommended — tsrs as the one checker (matches the repo today).**

- `site/package.json` devDeps: `tsrs` (pin the repo's revision, bump with it), `@astrojs/ts-content-mapper@0.2.0`. No `typescript` package needed for build, lint, tests or Playwright.
- `tsconfig.json`: `extends: "astro/tsconfigs/strict"`, `"types": ["bun"]`, `contentMappers: [{ "package": "@astrojs/ts-content-mapper", "extensions": [".astro"] }]`.
- Check: `tsrs -p site --runExternalCode` (one run covers `.ts`, configs, tests, `.astro` frontmatter and `<script>`; ~0.3 s on the spike).
- Lint: `TSRS_LINT_RUN_EXTERNAL_CODE=1 oxlint --type-aware` — the env var is required once the tsconfig has `contentMappers` (or give oxlint a lint tsconfig without the mapper).
- Rule: plain `<script>` only, never `lang="ts"`; keep page logic in `.ts` modules imported by the `<script>` so type-aware lint and unit tests reach it (they never see `.astro`).
- Cost: it is 7.1.0-beta semantics, not 7.0.2; prerelease from a third party; `--runExternalCode` runs `node_modules/@astrojs/ts-content-mapper/dist/server.js` (trust boundary — the package's README and tsrs SECURITY.md both call this out). When `typescript@7.1.0` ships (coming), `tsc -p site --runExternalCode` is a drop-in swap.

**Strict "7.0.2 only" alternative — tsc 7.0.2 + TS 6 for `.astro`.**

- `"typescript": "npm:@typescript/typescript6@6.0.2"`, `"@typescript/native": "npm:typescript@7.0.2"`, `@astrojs/check@0.9.12`. `tsc` (bin from the 7.0.2 alias) checks `.ts`; `tsc6` exists; `astro check` uses `require('typescript')` → TS 6.
- Verified: `node_modules/.bin/tsc --version` → 7.0.2, `require('typescript').version` → 6.0.3, astro check red/green as above.
- Cost: +77 packages (190 → 267), +24 MB TS 6 + Volar; two checkers whose diagnostics may differ; `astro check` 2.4 s vs 0.3 s; `astro check` itself says it "will be deprecated"; the `typescript` name points at 6, which confuses tools that read the version.

### What each 6.x need costs

- `astro check`: whole TS 6 + language-server stack, only to check `.astro`. Avoid with the mapper.
- Editor (astro-vscode / astro-ls): needs a classic-API TS; VS Code's built-in TS serves it, so the project need not install TS 6. Cost: editor diagnostics come from TS 6 while CI uses 7.x — small drift risk. Nothing to install unless someone selects the workspace TS.
- Everything else in the stack: no 6.x need.
